# 工作区审查与修正记录

日期：2026-09-27。审查范围为本轮工作区未提交的 Android 工作空间、独立全局AI助手、图片/语音、Markdown、工具详情及对应 Desktop 运行时改动。用户授权修复发现的问题、补充文档并提交。

## 已确认并修复的问题

### 1. P2：发送确认后，旧草稿被新页面的历史回调写回

触发：会话发送尚未返回时离开并重新进入同一会话。旧页面收到确认并清空已发送草稿；新页面仍持有旧副本，历史刷新或关闭页面时的整份 snapshot 保存再次覆盖它。

隔离探针实际观察：确认后 `text=""`，新页面历史返回后恢复为“任务已被服务端接受”，下一轮同步仍未纠正。包含图片时还可能保留已清除附件的引用。

修正：`AgentPanel.kt` 区分 `saveComposer()` 和阅读/历史状态保存。只有明确的编辑、附件变更和匹配的发送确认写入 composer 字段；历史/滚动保存先同步已发布草稿并保留它的 request ID、文字和附件。已关闭页面不能再次保存页面快照或发起发送。

回归：同一会话重入、延迟确认、延迟历史回调、下一条草稿保留；既有跨会话迟到发送和图片操作回归也通过。

### 2. P2：长工具交互永远显示首次缓存的状态

触发：工具交互超过历史预览上限，手机在任务执行中读取并缓存其全文。后续更新继续使用相同记录 ID，因此缓存中的 running/参数列表遮蔽后续 finished/结果记录。

隔离探针实际观察：服务端状态为 finished，页面仍是 running，全文记录只请求过一次。

修正：`store.rs` 对大工具交互按更新序号创建不同 UUID 的不可变全文快照；同一版本重复读取返回同一 ID，旧快照保持不变。快照仍关联原事件，历史清理会级联清理它们。手机沿用现有按 record ID 缓存的机制即可读取新版本，不关闭缓存、不清空历史。

回归：新旧快照 ID、正文、参数/结果更新、分页原文和清理行为；Android 验证版本变化后详情刷新。

### 3. P2：工具分析后的正常回复不再流式显示

触发：一次正常终端读取完成观察分析后，最后一条上下文的来源仍是 ObservationAnalysis。原判断据此隐藏了下一次正常回复，而非仅隐藏分析/压缩请求。

定向回归修复前明确失败：模型已输出“最终回复的第一段”，公开 live_text 仍是“先读取终端”。

修正：`host.rs` 使用明确的 Reply / Analyze / Compact 请求阶段；正常回复始终更新用户可见增量，内部分析和压缩不进入聊天流。模型调用、参数及工具授权不变。

回归：完成真实运行时工具/分析序列后，在最终回复尚未结束时检查 live_text 已更新；任务随后正常完成。

### 4. P2：批量工具调用丢失早期参数和结果入口

触发：同一工具交互产生超过 16 条更新。updates 的有界尾部淘汰了较早的 call_record_id / result_record_id，UI 又仅依赖该尾部生成详情入口。

修正：历史响应补充事件关联的独立 records 索引，排除内部全文快照，保持现有有界更新尾部。索引携带 tool_call/tool_result 来源，`AgentTimeline.kt` 据此分类，并避免通用“关联证据”覆盖明确的参数/结果标签。

回归：10 次调用、20 个真实记录，updates 仍限制为 16 条，20 个记录入口全部保留；Android 验证索引与更新去重后标签正确。
