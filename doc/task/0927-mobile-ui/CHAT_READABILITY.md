# 聊天可读性跟进（2026-09-27）

用户反馈：正常说明在刷新后消失，展开工具记录时大量重复“查看证据”按钮占满消息区。

## 确认原因与修复

- Desktop 只为不含工具调用的回复写入 `assistant` 历史；含工具调用的回复仅写 `interaction.tools`，导致同时输出的说明文字未进入可显示历史。现在将说明保存在同一 interaction 的 `text`，保持原有事件 ID、工具和模型上下文结构。
- 内部证据分析/上下文压缩曾共用可见流式缓冲。现在只让对话阶段更新可见流式文本；内部分析不会覆盖聊天正文。
- Android 将流式内容与持久历史在同一轮渲染中替换，并去除重复副本；对连续刷新和作用域切换增加滚动回调校验。
- 工具记录改为最多两行的工具/结果摘要与一个详情图标；正文中的说明单独可读。旧的展开状态不会再恢复成大量内联证据按钮。
- 长消息提供六行节选和全文入口；状态信息两行节选。详情保留完整内容、原始操作字段及带类型/编号的证据入口。
- 消息卡片使用不透明底色，终端仍在浮层背后保持连接，但文字不会与消息重叠。

## 验证

- Android debug 和测试包构建、lint 通过。
- Agent runtime 26 项测试通过，含带工具调用的说明文字持久化回归。
- Android 16 模拟器 5 项 UI/焦点测试通过，包含流式到历史切换、10 项证据的紧凑展示、长消息全文入口、详情读取与既有作用域/分页/输入焦点检查。
- 隔离端到端验证通过：详情 → 指定证据原文 → 返回聊天；终端读取、TUI 过滤与图片模型 HTTP 数据流保持正常。
- 截图及日志：`artifacts/mobile-ui/chat-readability/`。

Android APK 已安装到 `emulator-5586`。新增说明文字的服务端持久化修复需要使用重新构建的 Desktop；没有重启用户正在使用的 Desktop，也没有取消用户任务。说明保存修复作用于后续任务，本次未回填旧任务记录。
