# 账号登录与移动终端低延迟设计

- Status: Completed
- Updated: 2026-09-22

## 目标与范围

移动端与 Desktop 使用同一账号登录；App 展示自己的设备和会话，Desktop 只需 CLI 即可登录、查看状态和管理设备。普通使用流程移除管理员 token、长配对邀请与手工 key 授权。

改善移动端本地文字编辑、发送后的远端回显和持续输出时的操作响应。保留桌面唯一权威终端状态、原生移动 UI、WebRTC 优先/WSS 兜底、单控制者、输入去重与端到端加密。

本轮先完成源码调研与设计，经用户批准后实施账号登录与输入优化。关联原架构 `../0921-terminal-architecture/PLAN.md`，不改写其历史。暂不增加 Desktop GUI、团队共享、计费或 AI 功能，不替换终端引擎，不直接引入预测回显。

## 当前状态与证据

完整外部来源、机制对照与本地证据见 [RESEARCH.md](RESEARCH.md)。

1. Server 只有 `pairs` 表和配对/中转 API，没有用户、设备归属、登录或刷新会话。CLI `--pair` 依赖管理员 token；两端 App 导入 Invitation。
2. iOS 每 50ms 尝试刷新；Android 在每次刷新完成后再等 50ms。输入、刷新、历史在各端共用串行后台执行器；Rust `RemoteTerminal` 持有同一个 Mutex 进行阻塞网络往返。
3. `Channel::request` 是单请求往返模型，`send()` 的下一输入序号来自回复；输入 ACK 不携带 PTY 回显，画面需要后续 Poll。直连失败的当前重试门槛是 500ms，不能把该值当作正常延迟。
4. Rust 接收网络 delta 后仍生成全量 `RenderFrame`；两端 View 遍历全部 cells。iOS `TerminalSurface.updateUIView` 无条件赋值 screen；screen 的 didSet 无条件失效布局/绘制，字体与字宽在逐格循环中反复计算。输入框的页面状态更新可能触发这条路径，需要 profile 确认频率与占比。
5. `remote_bridge.rs` 每次请求 clone Client，clone 不共享 TCP stream，因此重新建立本地 IPC 连接。现有 IPC 两端已启用 TCP_NODELAY，不能把“添加 TCP_NODELAY”当作修复。
6. 已有验证证明能连通和输入，没有逐键延迟、UI 帧耗时的测量结果。现有试用服务已停止，本轮没有重启服务或模拟器。以上是源码证据，不是已实测的完整根因。

### A. 账号、设备与授权

首版采用自部署内置账号密码，避免必须接入外部身份供应商。用户已批准推荐默认值；新增现象按分段证据继续诊断。

初始化管理员通过 Server 本地管理命令创建普通用户；默认关闭公开注册。App 提供登录、账号信息、改密码、设备列表、移除设备和退出登录；忘记密码由管理员命令重置。公开注册、邮件找回和第三方登录后续扩展。

已实现 CLI 接口：

```text
ai-terminal auth login --server https://terminal.example.com
ai-terminal auth status
ai-terminal auth logout
ai-terminal devices list
ai-terminal devices revoke DEVICE_ID
```

登录交互读取用户名与隐藏密码，密码不放在命令参数或日志。保留现有终端/session 命令，不要求每次打开本地 Shell 登录；远程功能登录一次即可。用户切换账号时先停止旧账号远程连接，不能把旧设备/会话自动转给新账号。

- 数据：`users`、`devices`、`auth_sessions` 与短期连接授权；所有设备查询、会话路由与连接授权检查 user_id。设备记录含名称、平台、公钥、在线状态、撤销时间；在线状态由有期限的心跳决定。
- 认证：Argon2id 密码哈希；短时 access token、设备绑定的可轮换 refresh token，Server 只保存令牌摘要；登录限流、密码修改/重置后撤销相关会话。App 存 Keychain/Keystore；Desktop 优先系统凭据库，无凭据库的 Unix headless 环境使用明确受限的私有状态文件，Windows 保留系统凭据库，不能沿用临时目录保存长期登录状态。
- 设备：客户端首次登录自动生成设备密钥并登记，私钥不上传。Desktop Agent 维持在线注册和连接监听；同账号 App 自动发现设备，选择后查看会话，仍显式接管输入。
- 授权：Server 仅为同账号且未撤销的设备签发绑定双方设备 ID、公钥、权限、随机 nonce 和有效期的连接授权。采用成熟 Noise 库的双端静态身份认证握手，校验对方身份与授权，认证 WebRTC fingerprint；替代手工分发 NKpsk0 配对 PSK，不能把旧邀请整体存入账号数据库。
- 信任：首版明确以账号服务作为首次设备身份目录的信任根；已知设备固定公钥，变更要求重新登记。这可保护终端内容不被正常中转服务读取，但不承诺抵抗身份目录本身被攻陷后伪造新设备。若要求恶意目录也不能注入新设备，需要额外可信设备确认/恢复机制，不在此默认方案中暗中实现。
- 撤销：退出本设备使本设备会话失效；移除设备使对应令牌、在线连接、连接授权失效，释放输入权，保留桌面 Shell。直连仍受控制通道租约约束，断开控制通道不能无限期继续输入。
- 迁移：新版本登录为主入口；旧邀请与账号设备不自动互信，不静默认领旧 pairs。短期保留显式 legacy 模式以便回退，账号模式只接受账号授权，防止注销后仍被旧配对旁路访问。新建表采用增量迁移，保留旧数据备份。

替代方案：若选 OIDC，移动端用系统浏览器 Authorization Code + PKCE，Desktop 用 Device Authorization Grant（RFC 8628，需供应商支持），可通过手机浏览器完成无桌面浏览器环境的登录。用户/设备/授权层可复用，密码管理交给供应商；部署依赖与登录体验会改变。

### B. 输入与渲染

先做窄范围测量与可验证的局部优化，再改变传输协议，不通过单纯缩短轮询间隔掩盖问题。

1. 记录分段时间：UI 输入事件、客户端入队/发出、Agent 收到/PTY 入队、收到回显、应用 revision、呈现帧。以单调时钟测各端区间及客户端往返，不直接相减未同步的跨设备时间。只记序号、时长、队列长度和消息大小，不记输入内容或令牌。
2. 本地输入与终端状态解耦；iOS 按 session generation、revision、尺寸与 zoom 判断是否更新，避免 revision 在切会话后重复导致旧屏保留。只在尺寸/字体变化时更新布局；缓存字宽、行高、字体样式和颜色。用 Instruments 验证是否命中当前卡顿。
3. 保持同一远端客户端身份，复用 bridge 的本地 IPC 连接。保持现有输入顺序/控制权校验，错误后显式重连。历史查询不进入输入关键路径。
4. 新协议引入订阅屏幕、独立 InputAck、状态更新和恢复消息；Agent 状态变化主动通知 bridge，再推送移动端。网络收发运行在持续异步任务内，FFI 入队不持锁等待往返，前台只消费更新。进入后台按原合同释放控制并停止连接，不能依赖 iOS 无限后台运行。
5. 输入在同一 control epoch 内本地顺序编号，允许有界数量在途请求；ACK 不阻塞下一按键。设定在途窗口小于 Agent 的去重窗口，冲突重试拒绝，路径切换重发同一 ID 与原始内容。升级现有仅缓存一个 Reply 的 Channel；队列满时显式拒绝新输入，断线/会话 epoch 变化不自动重放不确定命令。
6. 输入/控制、画面、历史使用独立逻辑队列，公平调度并优先及时处理输入；网络拥塞不能无限积压。屏幕更新按接收方已确认 revision 合并/重建 delta，基线丢失时快照恢复；不能直接丢掉相互依赖的 delta，也不能丢输入或原始 PTY 字节。WSS 同一有序传输仍可能有队头阻塞，采用有界分块，不能宣称逻辑分队列等于网络隔离。
7. FFI 交付初始快照与增量行/单元格变更，UI 保存副本、只重绘受影响行和新旧光标区域；一显示帧内合并多次刷新。状态过期、resize、会话切换与恢复仍全量刷新。Android 用 Choreographer，iOS 用平台显示调度，不把 50ms 网络定时器当渲染时钟。
8. 首先保留现有输入框和发送语义，避免优化时改变用户操作合同。终端直接键入可作为独立后续体验调整，届时参考 SwiftTerm 的 UITextInput 与 Termux InputConnection，明确中文 composition/commit、退格、粘贴与功能键。预测回显同样后置，必须处理密码、TUI、IME 与纠错，不能直接把输入画成权威输出。

### 执行顺序

先建立性能基线并完成 UI/IPC 的局部修复；随后完成账号 Server → CLI/Agent → mobile-core → iOS/Android 登录与设备页；最后交付订阅协议、异步输入、增量 FFI/绘制和联合回归。实测确认逐帧 ACK 同样放大 RTT，因此输入与显示均采用 32 条有界在途窗口；显示按序重排、累积确认，切订阅用 state_sequence 划定边界，缺基线重新订阅快照。WSS 已可靠有序，不因 500ms 停顿重复重发；仅直连超时执行跨路径重试。账号改造与性能结果分别验收，最终端到端验证登录后连接与连续输入。

涉及 `crates/server`、`device-security`、`protocol`、`remote`、`desktop-agent`、`desktop-cli`、`mobile-core`、两端 App、绑定生成及部署说明。实现前明确新旧版本协商，不让旧端错误解析新增流式消息。

## 验证

只为关键合同新增自动化回归：账号隔离、刷新令牌轮换/并发刷新、密码重置与撤销、过期授权/重放/错误公钥；输入连续编号、乱序/重复 ACK、路径切换无重复执行、控制权抢占、订阅缺基线恢复、慢消费者内存有界、会话切换无旧帧覆盖。

性能对照使用固定设备与构建配置、80×24/120×40、空闲输入/持续输出/历史拉取三类负载；区分输入框本地编辑与终端按键回显。测 direct 和 WSS relay，注入 RTT 20/80/150ms、丢包 0/1%，每组至少 1,000 次按键事件，报告 p50/p95/p99、帧工作、队列深度及 CPU/RSS，明确模拟器与真机差异。

拟定验收目标（不是当前实测值）：本地编辑及终端绘制主线程工作 p95 ≤16.7ms；低丢包空闲链路回显 p95 ≤ 实测路径 RTT + 40ms；连续输入不随逐键 ACK 线性排队；持续输出期间队列保持有界、Ctrl-C 不排在完整历史之后。超标按分段证据修复，不以预测画面冒充低网络延迟。

执行 workspace 相关测试与 clippy、新版 iOS/Android 构建和本机 WebRTC/WSS 集成回归。不对纯字体缓存写镜像实现的测试，用 profile/相同场景前后对照验证。仅规划文档阶段不运行无关构建。实施时先检查设备环境，真机不可用则提供具体 HANDOFF；可用时按技能流程确认真机验证安排。

## 风险与回退

账号登录不能替代设备认证、会话控制和加密。尤其要验证旧配对不会绕过新账号撤销；管理员接口不能成为普通 App 的登录 API。

流式输入改变 Channel 去重/重试合同，需先完成确定性测试再切换两端。ACK 仍只表示入队，不表示命令成功；Agent 崩溃后的执行状态可能未知。显示帧可合并，PTY 输出解析和输入执行不可随意丢弃。

分阶段保留上一套可运行构建和数据库备份；legacy 回退必须显式选择，不能自动降级到较弱授权。性能优化先保留原传输作为对照，但不长期维护两套未经验证的生产协议。
