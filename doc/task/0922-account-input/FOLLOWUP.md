# 一致性优先的性能续作

日期：2026-09-22。用户授权继续研究并优化，明确可用性、一致性优先。沿用 M2012K10C / Android 12 真机、同一 Release 原生库构建方式、真实 PTY 与隔离账号。

## 最终改动

1. 新增 `poll_display`：一次返回同一时点的显示增量、控制状态、连接路径，减少原来的三次 FFI 调用。使用 `try_lock`，锁繁忙时返回无批次，不消费 dirty cells；下一显示帧取得累计变化。现有 `drain_update` 接口保留，iOS 行为兼容。
2. Android 使用自己持有的可变 cell buffer，增量只替换变化索引，不再每次复制整个 120×40 列表。初始帧仍复制隔离所有权；全量快照原子替换。整批检查尺寸、索引顺序、完整快照数量和 session generation/epoch 后才修改缓存；非法批次整批拒绝，切会话重建基线。
3. 输入的会话 ID、session/control epoch、序号分配与入队在同一次加锁中完成。修复此前“两次加锁之间切会话”的竞态；队列满时不消耗序号，失去控制权时不入队。
4. 后台连接/选择任务增加过时代次检查，旧回调不能覆盖当前选择。

网络协议、输入确认、重试窗口、权限、Noise/WebRTC 认证与状态 hash 校验未减少。所有 PTY 输出仍经权威解析器处理，所有收到的合法状态增量仍按序校验；这里只能延后本地呈现，不丢输入，不跳过协议增量，也不使用预测字符伪装回显。

## 方案取舍

试验过后台单消费者读取及事件通知：显示回调从 5–11ms 降到接近零，但持续输出和历史场景回显 p95 从约 111ms 升至 144–145ms。该方案已撤回，未作为默认代码留下；原始数据和实验源码放在 `build/android-followup/`，不进入产品代码。

最终保留更小的同一时点读取/不等锁方案。它仍有明确取舍：锁繁忙时要等下一显示帧，所以不承诺每个场景的回显延迟都更短。此前状态已经在 Rust 副本中保留并校验，延期不会损坏终端内容或改变命令执行语义。

## 对照方法

先扩展 FrameMetrics 采样，分别记录动画回调、绘制、布局、调度以及输入入队耗时。初始两个旧版基线与数个试验版结果均保留，未只挑选有利结果。

发现旧探针“调用完成后再睡 10ms”会导致不同版本输入速率不同。最终对照改成从入队开始计时、目标每 20ms 一个字符，每组 1,000 字符；每组另注入 60 个原生编辑事件。只保留一套活动 Agent 负载，旧版先测、新版后测，使用同一测试 APK 和设备。实际 1,000 字符输入耗时仍有差异：旧版 21.5/23.7/24.0s，新版 20.8/21.7/21.9s，因此并非严格等速实验，不对微小差异作因果断言。

设备 Wi-Fi、充电、系统负载与温度没有严格实验室控制。协调/账号流量经 USB 回环，终端状态在 WebRTC direct；没有做公网 WSS、TURN 或真实丢包测试。

## 最终数据

同一轮固定节拍对照，单位 ms，均为 p95：

| 场景 | 旧版整帧 | 新版整帧 | 旧版回显 | 新版回显 | 旧版本地编辑 | 新版本地编辑 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 80×24 空闲 | 10.47 | 9.19 | 79.16 | 86.72 | 5.60 | 6.18 |
| 120×40 持续输出 | 26.71 | 21.49 | 121.86 | 128.05 | 16.84 | 7.75 |
| 120×40 历史查询 | 30.67 | 25.14 | 105.53 | 129.28 | 7.89 | 10.02 |

回显定义为输入入队到原生 View 绘制回调，不是像素扫描完成；本地编辑为注入键事件到 EditText 内容变化。FrameMetrics TOTAL_DURATION 包含整个窗口和测试开销。

结果支持“降低部分整帧开销、改善持续输出时编辑响应”，**不支持“远端回显全面更快”**。历史查询场景回显和编辑 p95 均未改善；整帧 16.7ms 目标也未全面达标。新版另一次 10ms 目标间隔试验整帧 p95 为 9.33/17.38/18.78ms，但不与上述 20ms 对照混用。

## 正确性验证

- 36 项 Rust workspace 测试通过，包含新增“队列满不耗序号、请求身份同锁捕获”和“锁繁忙后仍完整交付累计变化、错误状态不伪装正常批次”。状态校验失败后旧副本保持不变。
- WebRTC 直连超时跨路径重试不重复执行的既有测试通过；账号隔离、撤销、控制权抢占、输入去重及状态基线测试继续通过。
- Android 完整真机验收通过，三组共 3,000 字符无丢失重复；6 轮快速切会话后 UI 与 Rust 已校验副本逐字段相等，包含单元格、尺寸、revision、光标等。
- 3 项显示一致性测试通过：软件 Canvas 的增量与全量像素相同；真实硬件 RenderNode 缓存与全量重绘的 PixelCopy 图像逐像素相同；非法索引/顺序/会话身份/残缺快照不部分改写旧屏。覆盖中文宽字符、组合字符、样式、4 种光标、缩放和尺寸变更（硬件测试覆盖缓存/光标，完整矩阵另由软件测试覆盖）。
- Android 两 ABI Rust 库、App/测试 APK、lintDebug 构建通过；iOS 两目标 Rust 库与 Xcode 模拟器 App 构建通过；workspace clippy `-D warnings`、fmt 和脚本语法检查通过。lint 仍有原有警告，不称为零警告。

证据：`build/android-followup/matched-before/results.json`、`matched-after/results.json`、`workspace-tests.log`、`clippy.log`、`consistency-shipping.log`、`ios-build.log`。其他试验数据同目录保存。

## 后续范围

进一步降低回显尾延迟，需要分开测量真实路径 RTT、桌面发布/快照恢复次数、Rust 校验/序列化与设备调度。目前不能仅凭窗口帧数据指定某一段为唯一瓶颈。状态 checksum/完整性校验、输入可靠性和控制权隔离仍是硬约束；不以删校验或放宽权限换取低延迟。

常用设备锁屏和前台核对规则仍按 [Android 调试说明](../../../deploy/ANDROID-DEVICE.md) 执行，未使用桌面坐标寻找应用。
