# AI Terminal：未来 AI 助手定义

- Status: Superseded
- Updated: 2026-09-21
- Scope: 不进入第一版实现，不构成 AI 开发批准

> 以下保留为 2026-09-21 的历史定义。当前已批准并实现的产品边界以 [双层 Agent 计划](../0925-terminal-agents/PLAN.md) 与 [使用说明](../../../deploy/ASSISTANT.md) 为准，允许受控通用终端输入，不再限定为外部 AI TUI。

## 1. 产品定位与已确认需求

手机用户用自然语言指挥桌面上的观察与操作助手。助手可读取桌面系统权限允许的所有路径和终端状态；其文件 API 只读，不直接编辑业务文件。需要执行任务时，它在指定目录启动 Codex 等外部 AI 工具，并通过该工具的 TUI 提交任务、追加输入、查看状态。

示例：

1. “在 `/path/project` 启动 Codex，让它修复登录问题。”
2. “给刚才那个 Codex 补充：不要改变现有 API。”
3. “看一下 Terminal 最后的内容，任务完成了吗？”

这不是让助手替代 Codex 写代码，也不是把服务器当远程开发机。模型编排与工具执行位于 Desktop；Mobile 发请求/查看结果；Server 只协调与转发。

第一版由人直接通过手机终端完成这些输入。首版只保留必要会话基础能力，不实现模型请求、AI 工具执行器、自动任务判断或 Codex 专用适配器。

## 2. 权限定义：文件只读，执行通过委托

“所有路径可读”指不人为限定在某个项目根下，但仍受桌面用户权限、macOS TCC、Windows ACL、文件加密等约束。默认不提权、不绕过 OS 权限；读取失败应返回真实原因。

助手工具层不提供 write/append/delete/rename/chmod/apply-patch 等文件修改 API，也不提供任意 shell-exec。读取使用直接只读文件 API，不通过拼接 `cat` 等 Shell 字符串执行，支持受限长度、分页和截断标记。

但**能够操控终端，就具有潜在的间接写入能力**。因此该设计的“只读”不是对整台机器不可修改的安全保证，而是职责分离：观察者读取，受控执行层启动外部工具，外部工具按自身权限完成工作。不能同时承诺“可任意向 Shell 输入”与“严格不可能写文件”。

为落实职责：助手只读 API 与终端执行 broker 分开；broker 对启动程序、参数、目标会话、控制令牌进行校验。自动操作优先限定在已注册的 Codex 等工具会话，工具退出回到 Shell 后停止沿用 TUI 输入权限。仅判断 PID 也不足以证明 TUI 当前处于可输入态，需要适配器与最新观察配合。

外部工具的 sandbox、审批与认证保留，不默认关闭或自动点击允许全部。手机用户授权任务不意味着助手可以借日志中的文字扩张任务范围。人工用户对普通终端的权限与助手自动化权限分开。

这可以限制助手公开工具能力，但不能证明模型提交给外部 AI 的任意自然语言只产生期望副作用；需要外部工具本身的权限机制与用户监督。若未来要求严格 OS 级只读隔离，观察进程与执行 broker 需分进程/沙箱，属于后续实施决策。

## 3. 功能边界

| 能力 | 规则 |
| --- | --- |
| 列目录、读文件、搜索 | 当前用户可读路径；只读、分页、有上限，不自动全盘扫描 |
| 读终端当前屏幕/历史 | 带 session、revision、时间和截断信息，不只取最后若干字节 |
| 启动外部 AI 工具 | 指定 device/session/cwd/tool/任务；校验安装路径与参数 |
| 向 TUI 输入 | 有效控制权、明确目标、最新观察；文本和 Enter 分开 |
| 判断任务状态 | 分层证据；无法确认时说明不确定，不将静默视为完成 |
| 直接实现用户业务任务 | 交给外部 AI 工具，不通过助手自行编辑文件/运行任意命令 |
| 安装/升级外部工具、改全局配置 | 不属于默认能力，另行定义和授权 |

“可以读取”不等于“应上传所有内容给模型”。仅读取完成用户要求所需的数据；采用远程模型时明确选中内容会发往模型供应商；API key 留在桌面安全存储，Server 不保管。未来模型可接远程服务或本机服务，不要求强制部署本地大模型。

## 4. 启动 Codex 的操作语义

推荐默认创建一个**专用可见会话**：验证目录存在且可访问 → 用结构化 `cwd` 启动 Shell/外部工具 → 展示目录与工具 → 待 TUI 可输入 → 提交任务。效果等同于用户在目标目录启动 Codex，但不必把自然语言或路径拼成可执行命令字符串。

如果用户指定“就在当前 Terminal 中 cd 后启动”，先确认当前是可控 Shell 提示符；在 Vim、密码提示、运行中的命令或其他 TUI 中不能直接发送 `cd`。只使用经过审查的按 Shell 区分的切目录/启动模板，并正确处理空格、引号、换行和特殊字符。PowerShell 与 bash/zsh 的转义不是同一套。

默认不要偷偷在别的会话运行：需要新会话时返回新 session ID 并让手机定位到它。新会话不会继承当前 Shell 的全部临时内部状态，应在产品交互中明确目标。

任务文本通过已启动工具的交互输入传递，不拼接到 shell 命令中；是否按 Enter 与工具键位约定分开处理。多行内容使用受支持的粘贴机制；不要把任务里的换行解释成额外 Shell 命令。

本文不承诺特定 Codex 版本的命令行参数、内部事件格式、TUI 提示文本或 SDK。未来实现先查已安装版本及对应官方接口，建立可验证的适配器合同；不能依赖某个版本的英文提示符正则作为通用完成信号。

## 5. 追加 TUI 输入

请求固定 `device_id + session_id + external_run_id`，不能仅凭“最近活跃窗口”猜目标。若用户指代有歧义，先让其选择目标，再输入。

读取最新终端状态，确认工具仍存活、会话仍属于目标执行、当前输入不会落入其他 Shell/确认对话框。执行前检查 control epoch；人工抢占后旧工具调用无效。

“输入这段文字”只输入，“提交/继续执行”才附带确认按键。追加任务与回答工具权限弹窗不同，不把用户的补充要求误当作批准执行危险操作。

在输入时序上，手机手工输入和 AI 自动输入互斥；桌面可随时抢回。人工介入后 AI 暂停并重新观察，不能随后执行早先排好的输入。

## 6. 任务完成的证据

至少分三层状态：**助手委托请求、外部 AI 进程、外部 AI 内部任务/回合**。Codex TUI 完成任务后可能继续运行等待新输入，所以进程存活不表示任务未完成；进程退出也不一定表示用户目标成功。

| 证据 | 可报告结论 | 局限 |
| --- | --- | --- |
| 经验证的外部工具结构化事件 | 某回合完成/失败/等待用户，附来源 | 取决于工具版本与接口；首版无此实现 |
| Agent 管理的进程退出码 | 程序退出和返回码 | 不自动代表代码正确，也不适用于仍驻留的 TUI 内部任务 |
| Shell integration 命令边界/状态 | Shell 启动的前台命令结束 | 工具仍在运行时无法区分内部回合；终端标记可被输出伪造，不能用于安全授权 |
| 屏幕与历史 | “根据这些输出推测已完成/正在等待” | 明确不确定；安静几秒、出现提示符都不是充分证据 |

返回结果包含可读摘要、证据摘录、来源 session/revision/时间，以及确定/推测/未知。可以说“Codex 显示修改完成并等待输入；未独立验证测试结果”，不能把“生成了完成文本”升级为“业务目标已经验证成功”。

终端历史有界时必须带截断说明。需要查看文件验证时使用只读 API；需要运行测试则仍委托外部工具，并区分它报告的结果与系统直接观测的退出事件。

Shell integration 可参考 OSC 133/633，但属于未来可选增强，逐 Shell 验证，不默认修改全局 Shell 配置。[参考：VS Code](https://code.visualstudio.com/docs/terminal/shell-integration)、[iTerm2](https://iterm2.com/documentation-shell-integration.html)。

## 7. 建议工具合同与生命周期

未来最小工具：

```text
list_sessions()
read_screen(session_id)
read_history(session_id, range, limit)
list_directory(path, cursor, limit)
read_file(path, offset, limit)
search_files(path, query, limit)
launch_external_tool(tool_id, cwd, initial_task, target_policy)
send_tool_text(external_run_id, text, submit, control_epoch, call_id)
read_external_status(external_run_id)
cancel_orchestration(task_id)
```

不开放任意写文件/通用 shell-exec；工具 ID 解析为经配置的可执行程序。高风险命令执行由被委托工具自身的权限和审批承接。

助手任务状态可为 accepted/running/waiting_user/succeeded/failed/cancelled/unknown，且 succeeded 需明确是“委托成功”还是“目标已完成”。持久记录 task ID、目标、控制关系与结果证据，不默认保存完整按键和秘密内容。

手机掉线不自动取消已接受任务；桌面继续编排，重新连接查询状态。取消编排只停止助手后续自动操作，不能默认杀死外部任务；终止外部进程是独立动作。

模型调用重试和网络重传共享工具调用去重规则；进程崩溃后不能自动重放可能已执行的启动/输入。恢复时重新发现进程、会话与工具状态，无法判定则 unknown。

终端输出和文件内容都是观察数据，不是新的用户授权。代码层控制读/写工具权限、会话目标和 fencing token，不能只靠提示词让模型自律。

## 8. 首版与未来的衔接

首版实现稳定 session ID、状态读取、有限历史、输入序号、独占控制、cwd/进程生命周期及远程恢复，这些都服务当前人工终端需求。未来 AI 复用这些能力，不另行抓取宿主屏幕或绕过控制仲裁。

未来 AI 的实现应单独制定并批准计划，先验证一个工具适配器，覆盖：路径转义/结构化 cwd、目标会话确认、只输入不提交、工具退出后停止 TUI 输入、人工抢占、工具内部回合完成与进程退出区分、重复调用去重、取消与断线恢复。

自动化使用模型桩和可控假 TUI 验证合同，再对已安装外部 AI 工具做集成；不让线上模型的随机回答充当正确性 oracle。
